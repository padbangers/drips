# Drips (Beads) — runbook

Everything needed to build, deploy and continue the Drips insert effect lives in this folder. Read this first;
`README.md` says what the plugin is and how users install it. The project is modelled on Overcast
(`../overcast`, the Clouds port): same framework, build/deploy scripts, MIDI port, modulation page and skin tooling.
Overcast's `CLAUDE.md` has the device findings both rely on (MPC sends no MIDI to effects, Q-Link behaviour,
drop-downs, focus frames); they are not repeated here.

## What this is

Mutable Instruments **Beads** (texture synthesizer, Clouds' successor; source published 2026-10-12 in
pichenettes/eurorack, MIT) as a native MPC OS insert effect, built with the sd88me/mpc-vst-plugins framework
(submodule, pinned to 818f574 like Overcast so its `patches/` apply). Name **Drips**, MPC folder
`Padbangers - VST - Drips`, `drips.so`, uid `PbBd`, MIDI port "Drips N".

Status (2026-10-13): **1.0.0 released** (tag `drips-v1.0.0`, catalog check OK), installed on the MPC X with the
zip's own `install.sh -y` and smoke-tested by the user (tabs, Q-Links, Seed pad, settings, save/reload). Bench on the MPC X: p99 9.9 %, worst block 11.1 %, PASS.
Graphics: the background is the user's (`assets/Background.jpg` →
`skin/drips_bg.jpg`); knobs, tags and the snowflake are Overcast's images as placeholders until Drips' own arrive.

## How the port works

- **Sample rates.** Beads runs its codec at 48 kHz (Bright Digital, Sunny Tape — the latter processes the wet path at
  24 kHz internally), 32 kHz (Cold Digital) or 24 kHz (Scorched Cassette, `ENABLE_HARDWARE_24K`). The qualities'
  character depends on that, so each MPC block is resampled to the module's rate, processed in blocks of
  rate / 4000 frames (the module's 4 kHz block rate; pots and modulation update per block) and resampled back.
  An output FIFO starts streaming once one module block of slack is buffered. Latency ≈ 1 ms. Buffer lengths are
  the module's (4 … 32 s).
- **Configuration changes** (quality, buffer stereo/mono, source input/wavetables) re-run `Processor::Configure()`,
  which clears the buffer, as on the module. The output fades out, the change applies, 8 blocks of silence, fade in.
  As on the module, nothing changes while frozen (the change waits for Freeze off); at most every ~0.3 s.
  `Configure()` (768 KB clear, reverb reset, resampler kernels) runs on a **worker thread**; the audio thread outputs
  silence while `configuring` is set. In the audio thread it cost a 244 % block in the bench's Q-Link sweep.
  `get_param("busy")` reports it (the test waits on it).
- **Resampler** is polyphase (kernels per fractional position, up to 441 × 36): 3× faster than table lookups per tap;
  it was half of the plugin's base CPU.
- **Seed.** `seed_mode` Latched = `SEED_BUTTON_STATE_LOCKED`, Gated = the SEED button state. Each SEED tap is a
  30 ms press (the wrapper reports momentary params back to 0 to the host, but the engine may not hear the release).
  The SEED *jack* is "patched" when Seed Input ≠ Off or a matrix slot targets Seed: MIDI notes (held = gate, a new
  note forces one low frame for a new edge, min. 2 ms high), the MPC clock (follows ppq while playing, runs on at
  the tempo when stopped) and/or the matrix gate. Patched + Latched = Beads' clocked mode (Density = divider /
  probability), so "Off" must stay the default.
- **MIDI:** `midi_pitch` (notes transpose) and `midi_split` (off: every note transposes and gates; on: channel 1 only
  transposes = the PITCH CV jack, channel 2 only gates = SEED, envelopes, velocity — like patching a sequencer's CV
  and gate). The module delays SEED by 2.5 ms so the pitch CV settles; here both arrive in the same host block,
  pitch first.
- **Skin (2026-10-13, as the user laid it out):** DRIPS = 4×4 block in Q-Link order (Time Size Shape Pitch / Random ×4
  / Density Feedback Reverb Dry/Wet / In Gain Out Gain Freeze + Quality), Quality and a 220 px SEED pad
  (`skin/seed_{off,on}.png`, placeholders) on the right; SETTINGS = seed mode/input, MIDI pitch/split, source,
  buffer with explanations. Rows are 117 px apart with r = 26 knobs: the minimum so knob frames don't touch.
  `post_build.py` finds the Freeze toggle by `_64x64`: keep `w=64 h=64`.
- **Attenurandomizers** keep their unpatched function (internal random). Matrix modulation is added to the knob
  (like CV with the attenurandomizer fully clockwise); `has_cv` stays false. Pitch: knob law with notches
  (`LAW_DETUNE`), + MIDI note − root, + 24 st × matrix.
- **Input stage** = the module's manual-gain path: hard clip in the digital qualities, biased soft clip in Scorched
  Cassette, crossfade by gain in Sunny Tape. No AGC (MPC levels are already line level).
- **Output:** Beads' own limiters, then Out Gain, a −1 dBFS stereo-linked limiter and a soft knee (from Overcast).
- **Delay mode** (Size > 0.99) crossfades in over 1.5 s — tests must wait for it.
- Not ported: AGC, buffer backup to flash, gate output on OUT R, calibration, the disabled advanced features
  (monophonic grains, trim).

## Build and deploy

Same machine setup as Overcast (Colima outside the Bash sandbox, VPN off for image pulls, bash 5, repo mirrored to
`~/.cache/drips-build` because the volume is exFAT).

```sh
colima start                  # outside the Bash sandbox
python3 skin/gen_params.py    # after changing the param list (keep enum Param in engine.cc in step)
python3 skin/gen_layout.py    # after changing the layout generator
./build.sh                    # -> build/drips.so + skin (runs skin/post_build.py); highest glibc must be <= 2.32
make -C test run              # native engine test, no Docker
./deploy.sh --yes             # copy to the MPC and register it (first time: restarts the MPC app — save first)
```

`./build.sh test` (the framework's host test at 818f574) fails the same way for Overcast: it feeds effects a NULL
input (crash inside the test host) and its "nudge" check contradicts patch 0002. Not a Drips problem.

Skin preview: as in Overcast's runbook, with `~/.cache/drips-build/port` and `Padbangers - VST - Drips`.

**Always check that MPC runs the new build** (`deploy.sh` compares the mapped inode; see Overcast's runbook).

## Framework and catalog (checked 2026-10-13 against sd88me/mpc-vst-plugins 2087458)

- The `.so` is built with the pinned framework (818f574): the wrapper was rewritten upstream and our three patches no
  longer apply (it has `HAS_SONG_POS` instead of patch 0001). Porting them means re-verifying the Q-Link zones and
  drop-downs on the device. **Packaging and checks use the newest tools** (`release.py`, `catalog_check.py`, `bench.sh`
  from a checkout of origin/main), so the installer matches the current template.
- Newest host test (`tools/test_port.sh` in a Linux container — on macOS it fails to link the weak
  `mpc_engine_changed`): the engine passes under ASan (NULL input, chunk, threads); its two FAILs are the new
  wrapper's option/int stepping, which this build doesn't ship.
- `os_compat` comes out `3.x` only: the old skin generator writes TUI objects of version 2 (MPC OS 2.15.1 uses 1).
- **Branding rule** (catalog README, #394/#404): no other company's name or logo in the skin, screenshot or plugin
  name; summary and tags may describe it ("from Émilie Gillet's open-source Beads"). The `mutable-instruments` tag was
  dropped from such ports. The skin text names no product.
- Release: `tools/release.py ... --version X.Y.Z --bench build/bench.txt --repo padbangers/drips --license MIT --id drips -o dist`,
  then `tools/catalog_check.py dist/<zip> --catalog --expect-id drips --expect-repo padbangers/drips`.
